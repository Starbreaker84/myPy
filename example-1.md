## 1.1 Предполагаемые классы знакомых программ

### Любое десктоп-приложение
Возможные классы:
- абстрактный базовый класс (идентификатор, координата x, координата y,)

### Web-приложение для оформления ипотеки
Возможные классы:
- заёмщик (идентификатор, ФИО, место работы, источники дохода, семейное положение и т.д.)

- место работы (название компании, адрес, род дейтельности, занимаемая должность и т.п.)
- классом может быть любая сущность, для описания которой можно привести три и более свойства, например, адрес заёмщика (страна, область, населённый пункт, улица и т.д.)

### Игра Super Mario Odyssey
Возможные классы:
- персонаж (здоровье, класс возможностей, одежда и т.п.)
- интерактивные предметы (активность, текущее положение, урон, прочность)

## 1.2 Пример классов с внутренней структурой
В качестве примера приведена класическая композиция, где один класс зависим от некоторых других, при этом у каждого имеется своя собственная структура.
Класс колесо и двигатель независимы и имеют свою структуру, класс автомобиля зависит от колеса и двигателя, имеет свою структуру и в качестве примера, приведен метод, базирующийся на внутренней структуре класса автомобиля.

```python
class Auto:
    model: str
    length: int
    mass: int
    engine: Engine
    wheel: Wheel

    def __init__(self, model, length, mass, engine, wheel):
        self.model = model
        self.length = length
        self.mass = mass
        self.engine = engine
        self.wheel = wheel


    def max_speed(self):
        return (40 + 40 * (1 / self.mass)
                + 40 * (1 + self.engine.power / 100)
                + 40 * (1 + self.wheel.grep / 100))
class Engine:
    name: str
    power: int
    hot: int

    def __init__(self, name, power, hot):
        self.name = name
        self.power = power
        self.hot = hot

class Wheel:
    name: str
    grep: int
    work: int

    def __init__(self, name, grep, work):
        self.name = name
        self.grep = grep
        self.work = work
```

Пример использования данных классов:
```python
    wheel = Wheel("pirelli", 30, 50)
    engine = Engine("v8", 50, 70)
    auto = Auto("bmw", 30, 50, engine, wheel)

    print(auto.model)
    print(auto.wheel.name)
    print(auto.engine.name)
    print("Wheel [" + auto.wheel.name + "] has grep with [" + auto.wheel.grep.__str__() + "].")
    wheel.grep = 20
    print("Wheel [" + auto.wheel.name + "] has grep with [" + auto.wheel.grep.__str__() + "].")
```

## 1.3 Пример побочного эффекта от передачи объекта по ссылке
В примере 1.2 как раз специально сначала выводится состояние колеса в составе автомобиля, затем меняется непосредственно в классе колеса, и далее мы видим что значение, которое лежит как бы в классе автомобиля тоже поменялось.

Так же можно привести такой простой пример: 
```python
    wheel2 = wheel
    print(wheel.work)
    wheel2.work = 20
    print(wheel.work)
```


Пояснение: создали колесо, затем присволили значение якобы второму колесу, но по акту износ с дорогой падает только у первого колеса, но автоматически и у всех колёс, которые, по сути, являются ссылками на оригинальное колесо. Стоит так же отметить, что проблема устраняется созданием независимых экземпляров классов.
